# Kroger Cart

A local page for building your weekly Kroger order out of what you actually
buy. It reads your purchase history, turns it into a staples list, and lets you
fill your kroger.com cart from staples, search, recipes and past trips in one
place. You still check out on kroger.com; nothing here places an order.

Built on a command-line tool generated by
[CLI Printing Press](https://printingpress.dev), which is also included and
usable on its own.

> **Unofficial.** Not affiliated with or endorsed by Kroger. It talks to the
> private API kroger.com's own pages use, signed in as you, so it can break
> whenever Kroger changes its site, and automated access may be against
> Kroger's terms of use. Use it on your own account, at your own risk.

## Set up with an AI agent

Open this folder in Claude Code, Codex, Cursor or any coding agent and say:

> Set up Kroger Cart by following SETUP.md.

It builds the app, signs you in from Chrome, saves your store, builds your
staples list and opens the page, asking you for the few things only you can
do.

## What the page does

- **Staples:** everything you've bought on two or more trips, most-bought
  first, built from your order history, with prices, pictures and stock.
- **Search:** anything on kroger.com, including things you've never bought.
- **Recipes:** named groups of products; adding one adds every ingredient on
  top of what's already in the cart.
- **Past trips:** open an old order and add any of it back.
- **Your Kroger cart**, alongside every tab: each Add and − / + edits it, and
  changes wait until you press **Update Kroger cart**, so you can see what's
  new, changed or being removed before anything is sent.
- **Your usual:** star the staples you buy every week, and **Add your usual**
  brings the cart up to them in one click.
- **Out-of-stock items can't be added**, from any tab; they're marked, and
  staples Kroger can't sell right now sit at the bottom.
- An estimated total, sale prices, and pickup or delivery, whichever you use.

## Requirements

- A **kroger.com** account. Ralphs, Fred Meyer, King Soopers, Smith's, Fry's,
  QFC and other Kroger-family stores use their own sites, which this doesn't
  support.
- A Mac with Google Chrome, signed in to kroger.com. (Other browsers work, but
  you'll copy your session by hand; see [AUTH-SETUP.md](AUTH-SETUP.md).) The
  page runs on your Mac and is only reachable from it, not from your phone.
- Go 1.26.4 or newer.
- A Kroger account with past orders, if you want the staples list.

## Setup

```bash
git clone https://github.com/bschm0622/kroger-cart.git
cd kroger-cart
go build -o kroger-pp-cli ./cmd/kroger-pp-cli
```

**1. Sign in.** With kroger.com open and signed in in Chrome:

```bash
./kroger-pp-cli auth from-chrome
./kroger-pp-cli doctor          # want: OK Auth
```

This reads your Kroger session from Chrome's cookie store. macOS asks once for
permission to use your keychain. Sessions last days, not months; when one
expires, the page offers **Import from Chrome** itself.

**2. Tell it your store.** Product search needs to know which store you shop
at. On kroger.com, search for anything, then open DevTools (⌥⌘I) → **Network**,
filter for `products-search`, and right-click that request → **Copy** → **Copy
as cURL**. Then:

```bash
pbpaste | ./kroger-pp-cli auth set-store -
```

Only the store headers are kept. Redo this if you switch stores.

**3. Open the page.**

```bash
./kroger-pp-cli serve
```

It opens <http://127.0.0.1:8787>. The first time, press **Rebuild from purchase
history** on the Staples tab to build your list. The server only listens on
your own machine and refuses connections from anywhere else. Ctrl-C stops it.

For a double-click launcher, put an alias of `scripts/Kroger Cart.command` on
your Desktop (in Finder, hold ⌥⌘ while dragging it there). Use an alias, not a
copy: it finds the app from where the original lives. It builds the app if
needed, starts the server, and opens the page; closing its Terminal window
stops it.

## Your data

Everything stays on your machine, in `~/.config/kroger-pp-cli/`:

- `config.toml`: your store headers and Kroger session.
- `staples.tsv`: your staples. Plain text, one item per line; lines without a
  leading `#` are your usual (the starred ones on the page).
- `recipes/`: one small TOML file per recipe.

Pending cart changes are kept in your browser until you send them.

## From the terminal

The same staples file drives two scripts, for when you'd rather type:

```bash
./scripts/kroger-staples              # build staples.tsv from your history
./scripts/kroger-weekly-cart --dry-run  # show what your usual would add
./scripts/kroger-weekly-cart          # add your usual to the cart
```

Like the page, the script leaves out anything Kroger says is out of stock, and
it never lowers a quantity already in your cart. `--clear` makes the cart
exactly your usual: it adds first and removes the rest after, so a failure
can't leave you with an empty cart.

`./kroger-pp-cli --help` lists every command, and there's an MCP server
(`./cmd/kroger-pp-mcp`) and a Claude skill (`SKILL.md`) for using it from an AI
agent. Problems signing in are covered in [AUTH-SETUP.md](AUTH-SETUP.md),
including a table of common errors.

## Command reference

### Getting set up

- **`kroger-pp-cli serve`** - Open the page (`--addr` to change the port, `--no-open` to not open a browser)
- **`kroger-pp-cli auth from-chrome`** - Sign in by reading your Kroger session from Chrome
- **`kroger-pp-cli auth set-store -`** - Save your store from a DevTools "Copy as cURL" on stdin
- **`kroger-pp-cli auth set-cookie -`** - Save a session copied by hand from DevTools, on stdin
- **`kroger-pp-cli doctor`** - Check the session and configuration

### cart

Read and fill your Kroger cart

- **`kroger-pp-cli cart get`** - Show what's in the cart now (`--id-only` prints just the cart id)
- **`kroger-pp-cli cart add`** - Add/update line items in your cart. Pipe the JSON body via --stdin (shape: {"lineItems":[{"gtin13":...,"quantity":N,"modalityType":"PICKUP",...}]}).
- **`kroger-pp-cli cart savings`** - Compute savings for a set of line items. Pipe JSON body via --stdin.

### customer_profile_profile

Your Kroger account profile (also an auth check)

- **`kroger-pp-cli customer-profile-profile`** - Get your customer profile (use to verify the session is authenticated)

### orders

Past purchases / order history

- **`kroger-pp-cli orders details`** - Get line items for past transactions. Pipe a JSON array via --stdin: [{"divisionNumber":..,"storeNumber":..,"terminalNumber":..,"transactionDate":..,"transactionId":..}].
- **`kroger-pp-cli orders history`** - List past purchase transactions (most recent first)

### products

Search and look up Kroger products

- **`kroger-pp-cli products get`** - Get product details for one or more gtin13s (comma-separated)
- **`kroger-pp-cli products search`** - Search products by keyword (returns items with UPC/gtin13, price, availability)

### usual

Kroger "your usual items" recommendations

- **`kroger-pp-cli usual`** - Get usual-product recommendations. Pipe JSON via --stdin: {"carts":[{"id":"<cart_id>","upcs":[..]}]}.


## Output Formats

```bash
# Human-readable table (default in terminal, JSON when piped)
kroger-pp-cli customer-profile-profile

# JSON for scripting and agents
kroger-pp-cli customer-profile-profile --json

# Filter to specific fields
kroger-pp-cli customer-profile-profile --json --select id,name,status

# Dry run — show the request without sending
kroger-pp-cli customer-profile-profile --dry-run

# Agent mode — JSON + compact + no prompts in one flag
kroger-pp-cli customer-profile-profile --agent
```

## Agent Usage

This CLI is designed for AI agent consumption:

- **Non-interactive** - never prompts, every input is a flag
- **Pipeable** - `--json` output to stdout, errors to stderr
- **Filterable** - `--select id,name` returns only fields you need
- **Previewable** - `--dry-run` shows the request without sending
- **Explicit retries** - add `--idempotent` to create retries when a no-op success is acceptable
- **Confirmable** - `--yes` for explicit confirmation of destructive actions
- **Piped input** - write commands can accept structured input when their help lists `--stdin`
- **Offline-friendly** - sync/search commands can use the local SQLite store when available
- **Agent-safe by default** - no colors or formatting unless `--human-friendly` is set

Exit codes: `0` success, `2` usage error, `3` not found, `4` auth error, `5` API error, `7` rate limited, `10` config error.

## Development

```bash
go test ./...                 # Go tests
cd e2e && npm install && npx playwright install chromium
npx playwright test           # the page, end to end
```

The end-to-end tests run the real page and server against `e2e/fakekroger`, a
stand-in for kroger.com with a small fixed catalog, so they never touch a real
account. The HTML report lands in `e2e/report/`.

## How it was made

The command-line tool, MCP server and skill were generated by
[CLI Printing Press](https://github.com/mvanhorn/cli-printing-press) from
recorded kroger.com traffic, then fixed by hand where the real site disagreed
with the recording. The page, the staples and recipe files, the scripts and
Chrome sign-in were built on top. `spec.yaml` is the API description it was
generated from.
